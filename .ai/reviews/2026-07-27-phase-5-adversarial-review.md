# Phase 5 Adversarial Review

**Status:** Passed
**Date:** 2026-07-27
**Scope:** PI-08 cargo, specialization independence, tenants, events,
progression, persistence, presentation, and packaging

## Review question

Could Phase 5 appear to add cargo and six Advanced paths while the underlying
shipments, shared resources, events, ratings, progression, save continuity, or
path independence remain decorative or silently depend on Passenger?

## Risks and required countermeasures

### Cargo could be a progress bar

Every shipment retains stable contract, class, flow, piece, mass, volume,
deadline, security, storage, location, task, and flight ownership. State
changes require compatible capacity and completed ordinary work. Deliberate
restore corruption must be rejected.

### Cargo could secretly require a passenger airport

The cargo-only fixture excludes terminal, security checkpoint, passenger
operator, baggage system, and concession content. Dedicated freighters must
complete all cargo classes and directions using runway, stand, road,
warehouse, staff, and handling capability only. Belly freight is a separate
interoperability proof.

### Specializations could remain an exclusive class selector

Capability bands derive from per-path evidence. Tests activate multiple paths
simultaneously, preserve the legacy Phase 2 selection only for migration, and
prove every individual Advanced fixture omits unrelated signature facilities.

### Shared resources could be summary prose

Mixed advancement requires two real Regional paths to contend for an ordinary
stand, team, service, or timetable resource and complete without blocked work
or cancellation. The shared resource and both owning operations retain stable
IDs in the event/query evidence.

### Events could be parallel scripted counters

All eight definitions must create references to ordinary flights, shipments,
visitors, parking, teams, services, closures, or timetable reservations.
Success is calculated from those child records. Tests break child references
and prove partial success, cleanup, cooldown, decline, and mid-event save/load.

### Tenants could disappear irreversibly

Requirement loss starts an explicit grace window with cause and remedy. Basic
fuel, maintenance, cargo, and concession recovery offers remain available;
failure cannot remove the last viable operating loop.

### Ratings or objectives could be invented by UI

Every rating change has a stored source, magnitude, time window, and group.
Overall values reproduce from contributions. Exactly three optional objectives
come from authoritative state and can be replaced without penalty.

### Schema migration could rewrite accepted Phase 1-4 saves

Schemas 1-5 migrate without modifying legacy domains. Phase 5 evidence is
derived only on explicit initialization. Boundary continuation, future-version
rejection, reference validation, and uninterrupted/resumed checksums are
required.

### New UI could repeat the earlier text-heavy prototype problem

Cargo, provider, event, and progression views use dedicated rounded templates,
concise cards, spatial world counterparts, and color-independent state. Figma
frames, equivalent-state captures, copy-density review, component gallery, and
the five-scale matrix are evidence; code existence alone does not pass.

### Shipping could omit content or include tooling

Source and IoStore inventories must match. Scans require zero runtime string
asset loads, required 3D assets, editor/MCP/test dependencies, external
aircraft files, or network requirements. The offline package must exercise the
Phase 5 fixture.

## Exit condition

This review passes only after focused and full automation, six short path
fixtures, visual comparison evidence, clean Development and Shipping packages,
content/provenance inventory, dependency scans, and recovery checks all pass.
