# GS-19: Special Events

**Status:** Approved baseline  
**Owner:** Authored events  
**Last updated:** 2026-07-25

## Outcome and scope

Occasional events create memorable operational variation without becoming a separate event-management career. This specification owns event offers, preparation, authored demand, scoring, rewards, and cleanup.

## Event model

Initial event families are airshow, GA fly-in, flight-school open day, charter/VIP movement, cargo surge, holiday passenger surge, emergency exercise, and notable visiting aircraft. Each event definition provides eligibility, notice window, duration, optional preparation objectives, traffic/demand changes, required capabilities, safety rules, success measures, reward, and cooldown.

The player can accept or decline an offered event without penalty. Accepted events reserve no resources automatically; the preview lists expected movements, visitors, parking, staffing, security, and closure needs. Events use ordinary flight, passenger, transport, service, and incident systems rather than parallel fake mechanics.

## Airshows

Airshows use an authored display schedule, spectator area, temporary airspace/runway windows, emergency readiness, and ground exhibits. Display aircraft follow safe scripted paths. The player manages airport operations around the published closure windows but does not fly aircraft.

## Resolution

Scoring is based on safety, required movements, controllable delay, visitor access, and optional preparation. Partial success is valid. Failure reduces the reward but cannot bankrupt the airport. After completion, temporary demand and objects leave through visible ordinary flows.

## Acceptance

Tests must prove offer/decline, preparation preview, ordinary-system integration, schedule conflict, partial success, cleanup, cooldown, and save/load mid-event. No event may require passenger-hub progression unless explicitly a passenger event.
