## Review checklist

- [x] World versus UI dominance matches the reference intent.
- [x] Primary, secondary, and contextual actions have a clear hierarchy.
- [x] Palette, surface treatment, outlines, and depth cues form one visual language.
- [x] Typography size, weight, casing, and spacing are coherent.
- [x] Panel density and whitespace support quick scanning.
- [x] Operational state remains legible without relying on color alone.
- [x] Mouse cursor remains visible and interactive in the gameplay viewport.

## Highest-impact mismatches

1. All six cards use one cooker-visible project-owned thumbnail family and the
   same visual identity language. The images are intentionally pictographic
   rather than the concept's more detailed world-location thumbnails.
2. Established, Regional, Advanced, and Major are now named explicitly, but
   their text rows remain denser and less glanceable than the concept's
   dedicated labeled band chips.
3. Selecting a path opens requirements, capability bands, current evidence,
   spatial footprint, business effect, next capability, and reward/outcome.
   These remain a flat text hierarchy rather than final icon-plus-state rows.

## Intentional differences

- Cargo, Advanced, and Major destinations are deliberately shown as
  future-locked because their owning gameplay phases are not implemented.
  Passenger is not given greater weight than the other specializations.

## Next bounded iteration

- Target: capability-band chips and inspector row hierarchy.
- Expected visual change: the reviewed identities remain, each capability band
  becomes a discrete state chip, and requirements/evidence/rewards become
  reusable icon-plus-state rows.
- Acceptance observation: every path remains equally prominent and its current
  versus future capability can be understood without decoding abbreviations.
